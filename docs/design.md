# 场景控制与渲染接口

2026-11-09。按已确认范围实现：单手/多手预设、手部整体位置和旋转、Camera.001位置和旋转、日光旋转、按JSON独立后台渲染。旧生成和评测入口保持独立。

## 边界

使用两个独立基础blend副本，普通Python负责校验、HTTP任务和启动Blender；只有Blender worker导入bpy。配置文件、命令行、HTTP共用相同校验和worker。

每只手用Empty根节点控制网格和骨架，保留原始世界矩阵及镜像负缩放，不重新分配权重。手部translation是基础位置上的世界坐标偏移，rotation_degrees是绕骨架基础原点的世界轴XYZ欧拉偏转，变换次序为T(offset) T(pivot) R T(-pivot)。相机position和rotation_degrees、日光rotation_degrees为绝对世界变换；未提供的轴沿用基础场景。

单手支持32种二值姿态，多手两只分别控制。仅Camera.001渲染，其他灯禁用。每批重新加载基础场景，每个样本先恢复基础变换，再应用批次配置与该样本覆盖，避免累积。JSON固定五指顺序，thumb X [-20,-40]，四指Z [60,80,60]，允许显式整十角度覆盖。

HTTP本机服务使用持久任务目录和单worker队列，提交立即返回id，状态queued/running/succeeded/failed/cancelled；支持取消和下载生成文件。重启后未完成任务标记失败而不假装成功。不接受任意Python代码；原图输出与出题评测分开。相同任务配置可重复执行，图像不承诺不同GPU逐像素一致。

保存不可变请求、有效配置和逐图实际变换清单。可选保存配置后的blend快照。输出目录按随机job id隔离，错误写日志。验证包括配置边界测试、Blender双手变换/绑定/镜像检查、单手和双手低分辨率渲染、HTTP提交/查询/文件获取。

## 两阶段规则配对扩展

按用户进一步确认，主入口分为configure_scene.py + scene_config.json（只布局并保存一份基础场景）和generate_dataset.py + generation_config.json（从配置好的blend按已有六条规则变化并渲染配对）。Stage2不重建手部根节点，不重置手部世界变换，未选中的手保持基础姿态。CLI自动读取最新成功配置的场景指针，也允许指定快照；API通过scene_job_id引用明确的已完成配置任务。

六条规则为数量保持220对、单指右移5对、双指右移10对、两种光照变换各32对、拉伸32对（单活动手）。合计331对，复用128张原图。双活动手各自独立应用同一规则，数量保持按每手分别定义。规则模块纯Python计算真值；Blender只执行姿态和投影；Pillow拼接输入输出图。L1/L2从已配置基础场景分别增减日光X角30°及相机世界X位置30；LS设日光Y60°及相机Y75。默认scene_config使用X0°/Y30°作为source。

## 网页配置与预览

用户确认的网页方案：现有本机HTTP服务托管原生HTML/CSS/JS，左侧表单按手/相机/日光分组，右侧展示Blender快速预览；模式和姿态可切换。修改停止1秒后串行渲染当前配置，预览保持画幅比例并使用8采样，陈旧结果不覆盖新版本。参数版本号关联预览与场景确认；任意第一阶段修改使第二阶段确认失效。确认使用正式尺寸独立保存快照，生成任务固定引用该快照，不受后续表单修改影响。

网页支持现有六规则选择、活动手、数量、种子、任务进度/取消、配对结果展示、场景JSON导入及两种JSON导出。无前端构建依赖。defaults从场景导出的完整preset读取，模式切换重置对应基础参数。网页不覆盖源JSON或CLI的latest指针，刷新前需导出编辑。浏览器端实际测试覆盖最新参数预览、坐标修改、模式与手势、确认失效、生成、配置导入导出和窄屏布局。
